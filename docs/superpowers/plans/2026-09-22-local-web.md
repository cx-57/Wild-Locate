# Local Web App Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task if native execution is selected; use superpowers:subagent-driven-development if delegated execution is selected.

**Goal:** Run a usable local browser version with `wildlocate web`.

**Architecture:** Serve bundled HTML/CSS/JavaScript from a loopback Python HTTP server. Send analysis requests to the existing JSON-lines prediction subprocess, with one cancellable job at a time. Reuse the existing data, models, and Leaflet assets.

**Tech Stack:** Python standard library, HTML, CSS, JavaScript, Leaflet; no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-22-local-web-design.md`

## Global Constraints

- Bind only to `127.0.0.1`; do not publish a public website.
- Preserve `wildlocate` desktop behavior and the existing init/status commands.
- Support point analysis and 81-point regional analysis at 10, 25, or 50 km.
- Keep the full results table collapsed by default.
- Reuse bundled models; training and account management remain in the desktop app.
- Reuse the current worker entry point: `python -m wildlocate.core.worker predict`.
  The older specification named `prediction_worker`, which has since been consolidated.

## Review Focus

- A cancellation arriving alongside a result must not restore cancelled results.
- Missing map tiles must leave manual coordinates and textual results usable.
- A state with no models must disable Analyze and explain why.
- A malformed/oversized/cross-origin request must not start a subprocess.
- Installed distributions must contain every required browser asset.

## Task 1: Cancellable local server

**Files:** Create `wildlocate/web/server.py` and `tests/test_web.py`.

**Interfaces:** `create_server(port=8765)` returns an HTTP server bound to loopback;
`serve(port=8765, open_browser=True)` prints the URL and serves until interrupted.
A `JobManager` owns one subprocess and the latest job. It exposes `start(payload)`,
`status(job_id)`, `cancel(job_id)`, and `close()`. Job objects contain `id`, `status`
(`running`, `complete`, `error`, or `cancelled`), and either `result` or `error`.

- [ ] Write failing HTTP tests using an ephemeral loopback port and a server thread.
  Exercise missing token, bad Origin, unsupported state, invalid coordinates,
  malformed JSON, oversized body, and unknown static paths. Example assertions:

  ```python
  connection.request('GET', '/../../pyproject.toml')
  self.assertEqual(connection.getresponse().status, 404)
  connection.request('POST', '/api/jobs', '{}', {'Content-Type': 'application/json'})
  self.assertEqual(connection.getresponse().status, 403)
  ```

- [ ] Write worker lifecycle tests using a small Python subprocess fixture that
  reads JSON and either responds or waits. Assert completion, error, busy rejection,
  cancellation, and successful restart. A cancelled job stays cancelled even if
  its reader thread later finishes.
- [ ] Run `.venv/bin/python -m unittest discover -s tests -p test_web.py -v` and
  confirm missing server behavior fails.
- [ ] Implement the allowlisted routes:

  ```text
  GET  /                 browser HTML
  GET  /style.css        browser styles
  GET  /app.js           browser code
  GET  /vendor/...       explicit Leaflet assets
  GET  /api/config       states, bundled species, centers, per-launch token
  POST /api/jobs         validate then create analysis job; return 202 + id
  GET  /api/jobs/{id}    return latest job state
  POST /api/jobs/{id}/cancel  cancel current matching job
  ```

  Accept only JSON objects with species, region, numeric finite latitude/longitude,
  and optional radius_km. Reject unknown fields, booleans as coordinates, invalid
  state/model/radius, invalid Host, and bodies larger than 8 KiB. Require the
  per-launch token in `X-Wildlocate-Token` for POST, and reject foreign Origin.
  Serve assets from a fixed path map; never use user input as a filesystem path.

- [ ] Use subprocess pipes and `communicate` in a background thread so stderr is
  drained safely. Prepend the package root to child PYTHONPATH. Guard manager
  state with a lock. Terminate and reap cancelled jobs before accepting another.
  On shutdown, stop and reap the worker. Limit retained state to the latest job.
- [ ] Rerun the server tests; commit only this task's files after success.

## Task 2: Browser interface

**Files:** Create `wildlocate/web/index.html`, `style.css`, and `app.js`.

**Interfaces:** Consume Task 1 routes. Keep a frontend selection version and active
job ID so asynchronous responses cannot overwrite newer selections.

- [ ] Build semantic HTML with labeled species/state selects, coordinate inputs,
  point/regional toggle, radius choices, Analyze/Cancel buttons, status region,
  map, result summary, legend, `<details>` score table, and JSON export button.
- [ ] Style compact controls beside a large map on wide screens and stack them on
  narrow screens. Use the existing green/cream visual palette and small markers.
- [ ] Implement config loading and selection validation. An empty model list disables
  Analyze with an explanatory message. Manual coordinates work without map tiles.
- [ ] Implement analysis request/poll/cancel flow:

  ```javascript
  const response = await fetch('/api/jobs', {
    method: 'POST',
    headers: {'Content-Type': 'application/json', 'X-Wildlocate-Token': token},
    body: JSON.stringify(selection)
  });
  ```

  Check every HTTP status; display server errors via `textContent`. Poll only the
  current job; stop polling on completion/error/cancel. Disable selection controls
  while running, and reset the result when inputs change.
- [ ] Render point results and feature values; render regional circle, percentile
  colors, unavailable gray dots, per-point popups, counts, mean score, and table.
  Do not interpolate user/backend strings into HTML. Download JSON using a Blob
  and revoke its URL afterward.
- [ ] Run `node --check wildlocate/web/app.js`. Exercise the browser with deterministic
  sample responses, including missing-data results, no species, request failure,
  cancellation, and a late response from a cancelled job. Inspect wide and narrow
  screenshots. Verify map points and the full score table match the response count.
- [ ] Commit the frontend after those checks pass.

## Task 3: Command, packaging, and live verification

**Files:** Modify `wildlocate/cli.py`, `pyproject.toml`, and `README.md`;
extend `tests/test_web.py` for CLI parsing.

- [ ] Write a CLI test patching `serve`, invoking `main()` with
  `['wildlocate', 'web', '--port', '8766', '--no-browser']`, and checking arguments.
  Verify default desktop dispatch still calls `cmd_gui`.
- [ ] Add the subcommand and lazy server import:

  ```python
  web = subparsers.add_parser('web', help='Open the local browser app')
  web.add_argument('--port', type=int, default=8765)
  web.add_argument('--no-browser', action='store_true')
  ```

  Route it to `serve(port=args.port, open_browser=not args.no_browser)`. Validate
  port range, report occupied ports clearly, and shut down cleanly on Ctrl+C.
- [ ] Add `web/*.html`, `web/*.css`, and `web/*.js` to package data. Retain existing
  Leaflet assets. Build a wheel without downloading dependencies, inspect its ZIP
  entries, and assert all allowlisted asset paths are included.
- [ ] Document `wildlocate web`, port selection, stopping the server, internet needs
  for tiles, and the first-version limitation to bundled models.
- [ ] Run the full existing suite, including the macOS Qt initialization step needed
  by desktop tests. Report any failures, even unrelated ones.
- [ ] Start the installed web command. Run a real Bobcat assessment at
  42.37, -72.28 with a 25 km radius; verify 81 result points and JSON export.
  Exercise cancellation/restart and then point analysis.
- [ ] Request one independent review, fix blocking findings, and rerun affected checks.
  Commit only this task's files; leave unrelated local changes intact.

## Plan self-review

is covered above. The worker path was updated to match the current checkout.
Public deployment, account management, and training UI are intentionally excluded.
Recommended execution: native in this session, because the three tasks share
server/frontend contracts and the existing backend needs no redesign.
